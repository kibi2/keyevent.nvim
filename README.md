# keyevent.nvim

**Time-based key event detection for Neovim.**

`keyevent.nvim` detects keyboard input events and classifies them according to the timing of consecutive key presses.

It provides a common event layer for plugins that want to use the **time axis of key input** in addition to ordinary Vim key mappings.

`keyevent.nvim` was originally developed as part of [`rush.nvim`](https://github.com/kibi2/rush.nvim), and was separated into an independent plugin so that other plugins can use the same key event detection.

For example, a sequence such as:

```text
j
jj
jj + hold j
```

can be distinguished as different events depending on the timing between the keys.

The basic idea is:

> **A key event is more than just the key itself. Its timing can carry meaning.**

## Features

* Detects key input using Neovim's `on_key`
* Distinguishes clicks, taps, hold starts, and repeats
* Measures the interval between key events
* Tracks repeated key counts
* Tracks hold time
* Tracks key sequences
* Handles modifier keys
* Provides the same event information from both `on_key` and key mappings
* Supports multiple event callbacks
* Provides a diagnosis command for measuring key repeat timing

## Installation

Using lazy.nvim:

```lua
{
	"kibi2/keyevent.nvim",
	config = function()
		require("keyevent").setup({
			interval = {
				delta = 20,
				tap = 500,
			},
		})

		-- Uncomment the following lines to try the on_key example.
		-- In insert mode, type "kj" to leave insert mode.
		-- require("example.on_event")

		-- Uncomment the following lines to try the keymap example.
		-- Press n normally to repeat the search.
		-- Press and hold n to show the search history.
		-- require("example.keymap")
	end,
}
```

## How it works

`keyevent.nvim` watches keyboard input and creates a `KeyEvent` for each relevant key.

A simplified sequence might look like:

```text
j       → click
j       → tap
j       → hold
j       → repeat
j       → repeat
```

The classification is based on the interval between consecutive key events.

For example:

```text
j
↓
j
↓
j ───────────── hold
              ↓
          key repeats
```

The event contains information such as:

```text
key : 押したキー
prev_key : 前回のkey
meta : 押していたメタキー
prev_meta : 前回のmeta
interval : 前のキー入力からの経過時間
nt : 連続タップ回数
nh : 押し下げ回数
nr : repeat回数
hold_start : 押し下げを開始した時刻
```

This allows another plugin to decide what the sequence means.

`keyevent.nvim` does not decide what a particular key sequence should do. It only provides the event information.

## Key events

The main event types are:

| Event        | Meaning                                       |
| ------------ | --------------------------------------------- |
| `click`      | A key press separated from the previous input |
| `tap`        | A key pressed again within the tap interval   |
| `repeat`     | A key generated by holding the previous key   |
| `repeat_end` | The end of a key repeat                       |

The exact classification depends on the configured timing thresholds and the key repeat characteristics of the system.

## Using events

A plugin can register an event callback with:

```lua
require("keyevent").on_event(function(event)
	-- use event here
end)
```

Multiple callbacks can be registered.

For example, an event consumer can inspect the current key:

```lua
require("keyevent").on_event(function(event)
	if event.key == "j" then
		-- ...
	end
end)
```

The callback receives a `KeyEvent` containing the timing and sequence information.

## Using key mappings

`keyevent.nvim` can also be used from an expression mapping.

For example:

```lua
local KeyEvent = require("keyevent.keyevent")

vim.keymap.set("n", "n", function()
	local event = KeyEvent.keymap_event("n")

	if event.nr == 1 and event.nt == 2 then
		return ":history /<Enter>"
	elseif event.nr > 1 and event.nt == 2 then
		return ""
	end

	return "n"
end, { expr = true })
```

This example keeps the normal behavior of `n`, while using a different action when `n` is pressed and held.

The important point is that the mapping receives the same kind of timing information that is available to `on_event()`.

## Key sequences

Recent key events can be obtained with:

```lua
KeyEvent.keys(10)
```

For example, a plugin can use the key sequence to implement its own multi-key behavior.

An example included with `keyevent.nvim` uses this to make:

```text
kj
```

leave Insert mode.

```lua
local KeyEvent = require("keyevent.keyevent")

require("keyevent").on_event(function()
	if vim.fn.mode() == "i" then
		if KeyEvent.keys(2) == "kj" then
			local keys =
				vim.api.nvim_replace_termcodes(
					"<BS><BS><Esc>",
					true,
					false,
					true
				)

			vim.api.nvim_feedkeys(keys, "n", false)
		end
	end
end)
```

## Timing

Timing values are measured in milliseconds.

The classification uses several timing values, including:

* key repeat interval
* hold detection interval
* tap interval
* timing tolerance (`delta`)

The timing of key repeats differs between systems and keyboard configurations.

For this reason, `keyevent.nvim` can obtain timing information from the operating system and also measure observed input timing.

The effective value can be determined from the available configuration and timing information.

## Diagnosis

Run:

```vim
:KeyEvent diagnosis
```

A floating window shows the timing information detected by `keyevent.nvim`.

It can be used to check the timing of your keyboard and compare:

* configured values
* operating system values
* analyzer values
* measured intervals
* suggested configuration

This is especially useful when the actual key input timing differs from the local operating system settings.

For example, keyboard input may be coming through a remote input system rather than directly from the local keyboard.

Press `<Esc>` to close the diagnosis window.

## Configuration

The default configuration is designed to work with the timing information available to `keyevent.nvim`.

A configuration can override the timing values:

```lua
require("keyevent").setup({
	interval = {
		delta = 20,
		tap = 500,
	},
})
```

`delta` defines the tolerance used when comparing measured intervals.

`tap` defines the maximum interval treated as a tap.

他に二つのパラメータがあります。

`delay` キーを押し下げてからリピートが始まるまでの間隔

`interval` キーリピートの間隔

この二つはkeyevnt.nvimがtoolを利用してosに問い合わせて自動で取得します。
* tools/macos/keyevent-macos
* tools/windows/keyevent-win.exe
* tools/X11/keyevent-x11
ですがlinux waylandに対応したツールは準備していないのでos問い合わせは失敗します。
osに対する問い合わせが失敗した場合は統計的に値を推定して使用します。
またキーボードを複数の計算機で共有している場合は正しい値が取得できません。
tap, repeat などの判定がうまくいかない場合は診断ツールを使用してdelay, intervalの値をsetupを使って指定してください。

All timing values are in milliseconds.

## Why?

Vim key mappings normally describe the meaning of a key based on:

* the key itself
* the current mode
* the preceding key sequence
* counts and other Vim state

`keyevent.nvim` adds another dimension:

> **the time between key presses.**

This makes it possible to build key mappings where:

```text
key
key + key
key + hold
key + repeat
```

have different meanings without requiring every plugin to implement its own keyboard timing detection.

`rush.nvim` was the original motivation for this mechanism. Its motion acceleration needs to distinguish ordinary motion, repeated taps, and held-key repeats.

By separating that mechanism into `keyevent.nvim`, the same event model can be used by other plugins.

## Requirements

* Neovim 0.10+
* A system with key repeat support

## Limitations

The exact timing of key events depends on:

* operating system
* keyboard
* keyboard repeat settings
* terminal
* remote input systems

Therefore, timing values may need to be adjusted for a particular environment.

Use:

```vim
:KeyEvent diagnosis
```

to inspect the timing available in your environment.
